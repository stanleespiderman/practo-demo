# Practo interface demo — review revision 2

An independently developed, Practo-inspired patient and doctor app using fictional people and records. The Android implementation is **native Kotlin + Jetpack Compose**, with no WebView. `dist/` is a separate browser review of its design and interactions, not the Android app packaged as a website.

**No APK or AAB has been generated. APK packaging is on hold pending the user's final approval.**

## Doctor workspace added

Ten fictional doctor profiles now have an assigned-patient inbox, manual chat, private notes, Summary & Rx editor, demo medical documents/PDF export, calendar, demo billing, reports, feedback, health-feed drafts, reminder drafts, inventory and editable profiles. Open **Doctor workspace** from Home or Account. Full behaviour and limitations are documented in [docs/DOCTOR-WORKSPACE.md](docs/DOCTOR-WORKSPACE.md).

Automatic replies are now off by default. All medical documents carry a prominent DEMO mark. Real backend messaging and clinical services remain unconnected. The Android source was extended alongside the separate browser preview; its compilation/device run remain unverified.

## What's included

- Responsive home, doctor discovery/profiles, speciality browsing, consultation list/details, local chat, records, account/profile, family, medicines, lab tests, surgeries, plans, articles, appointments, orders, insurance, reminders, payments, ABHA and help sections.
- The wider app sections are navigable UI demonstrations. External services, real booking/payment, calls, arbitrary file uploads, insurance and ABHA verification remain unavailable. Doctor-side local scheduling and demo-document sharing are implemented. They do not show false success states.
- Persistent fictional consultations and per-consultation text histories, status/unread counts, automatic demo replies, patient/test-doctor role switching, failed delivery simulation and retry, empty-search results and error recovery.
- One canonical editable data file: `dist/seed-data.json`. Copy it to `android/app/src/main/assets/seed-data.json` after edits, then reset demo state to see seed changes. `tests/check-source.mjs` enforces identical copies.
- Proposed participant-only Supabase schema and an honest list of remaining integration work under `backend/`.
- Research notes, verification results and browser screenshots under `docs/`.

## Browser review

Serve `dist/` over HTTP, for example `python3 -m http.server 8080 --directory dist`. Open `/` for the responsive app, or `/mobile.html` for three live patient mobile design previews. `/doctor-mobile.html` reviews the new doctor screens at 360 pixels. These previews share the same local data.

Core path: Home → My consultations → View consultation → Continue consultation. The active consultation is `DEMO-10482` with fictional Dr. Ananya Rao. Search by name, speciality or consultation ID.

Open **Demo controls** to disable automatic replies, choose a local role, simulate offline or fail the next message. Send once, wait for Failed, then retry. For two local test sessions use two tabs at the same origin; open Doctor workspace in the second and select the doctor assigned to the conversation. This is same-browser storage synchronization, **not real multi-device messaging**.

Data is stored in localStorage. The static app must initially load from the server; it is not a PWA and a fully offline cold start is not supported. Once loaded, local messaging and simulated offline behaviour work. Clearing site data resets the demo. No personal data is requested.

## Android source setup — APK gate remains active

Requirements: Android Studio with JDK 17 or newer, Android SDK platform 35 / build-tools 35.0.0, Gradle 8.11.1. AGP 8.9.2 and Kotlin 2.1.20 are pinned; dependencies resolve from Google and Maven Central.

1. Open the `android/` directory in Android Studio.
2. Configure the local SDK path through Android Studio or an untracked `local.properties` file containing `sdk.dir=/your/android/sdk`.
3. Sync Gradle. Do not run or assemble the app until APK approval.
4. Non-APK verification once the SDK is available: `./gradlew :app:compileDebugKotlin :app:testDebugUnitTest`.
5. Only after the user's final approval: `./gradlew :app:assembleDebug -PapkApproved=true`. The resulting APK would be under `app/build/outputs/apk/debug/`.

The task graph blocks packaging/assembly/install/bundle tasks unless the explicit approval property is set. Do not supply that property before approval. Neither an APK nor an AAB is included.

`DemoRepository` stores atomic JSON in Android app-private storage. The ViewModel owns all mutable data and message delivery. Rotation/navigation state uses Compose saved state. Back handling is native; chat uses `imePadding`, a lazy list and an IME Send action. The app does not access a network backend. The role selector is explicitly a development demo; it is not authentication or a production access boundary. The entire app contains fictional data only.

## Verification limits

The browser review was run and tested. Kotlin and Gradle source passed the Kotlin parser/formatter; this is **not** a successful Android compilation. No Android SDK, emulator or device is available in the current workspace, so Kotlin dependency/type checking, Android lifecycle behaviour, keyboard resizing and native screenshots remain unverified. A real-device test pass is required after APK approval.

The design is research-based. Public Play Store images show selected marketing screens, not every current app state. Original illustrations replace photographic assets, and unseen screens are consistent approximations. This is not a pixel-perfect or functionally complete clone of Practo's production service.
